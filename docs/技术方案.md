## 1 · 系统架构

### 1.1 整体架构（Layered）

### 1.2 关键数据流（用户提交代码 + Agent 追问）

```text
User: 在 Monaco 写代码 → 点"运行"
  ↓ [Client]
Zustand store 更新 code state
  ↓
Client 调用 runInSandbox() → Web Worker
  ↓
Worker 执行代码 + 测试用例 → postMessage 结果
  ↓
Client 收到 TestResult[] → 更新 UI
  ↓
Client 自动发送 message 给 Agent：
  "code: <代码>, results: <结果>"
  ↓ [Server Action: continueSession]
Server 调用 Agent Loop:
  - 组装 prompt (round-specific)
  - 调用 DeepSeek (streamText)
  - Agent 返回 tool call: check_edge_case(code, edgeCase)
  - Server 执行工具（LLM 判断或代码分析）
  - Agent 生成下一段追问
  ↓
Server 流式返回 → Client 打字机渲染
  ↓
Session 状态入库（localStorage / Supabase）
```

### 1.3 三层抽象（可测试性）

- **UI 层**（`app/`, `components/`）：只做展示 + 事件转发
- **业务层**（`lib/`）：Agent Loop / Sandbox / Repository —— **无 React 依赖，可单元测试**
- **数据层**（`lib/repo/`）：Repository Pattern，本地/远程可切换

## 4 · 核心模块设计

### 4.1 Web Worker 沙箱

**文件**：`lib/sandbox/`

**主线程 API**：

```typescript
// lib/sandbox/runner.ts
import type { TestCase, TestResult } from './types'

export async function runInSandbox(
  code: string,
  cases: TestCase[],
  options: { timeoutMs?: number } = {}
): Promise<TestResult[]> {
  const timeoutMs = options.timeoutMs ?? 3000
  const worker = new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' })

  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      worker.terminate()
      reject(new Error(`Execution timeout after ${timeoutMs}ms`))
    }, timeoutMs)

    worker.onmessage = (e) => {
      clearTimeout(timer)
      worker.terminate()
      if (e.data.type === 'result') resolve(e.data.results)
      else reject(new Error(e.data.error))
    }

    worker.onerror = (err) => {
      clearTimeout(timer)
      worker.terminate()
      reject(new Error(err.message))
    }

    worker.postMessage({ type: 'run', code, cases })
  })
}
```

**Worker 内**：

```typescript
// lib/sandbox/worker.ts
type RunMessage = { type: 'run'; code: string; cases: TestCase[] }

self.onmessage = async (e: MessageEvent<RunMessage>) => {
  if (e.data.type !== 'run') return

  const { code, cases } = e.data
  try {
    // 用 new Function 编译用户代码
    // 用户代码约定：默认导出被测函数，或 return
    const fn = new Function(`${code}\nreturn typeof _default !== 'undefined' ? _default : (typeof myFn !== 'undefined' ? myFn : undefined)`)()

    if (typeof fn !== 'function') {
      throw new Error('No function exported')
    }

    const results: TestResult[] = []
    for (const c of cases) {
      try {
        const actual = await Promise.resolve(fn(...c.input))
        results.push({
          passed: deepEqual(actual, c.expected),
          actual,
          expected: c.expected,
        })
      } catch (err: any) {
        results.push({
          passed: false,
          expected: c.expected,
          error: err.message,
        })
      }
    }

    self.postMessage({ type: 'result', results })
  } catch (err: any) {
    self.postMessage({ type: 'error', error: err.message })
  }
}

function deepEqual(a: unknown, b: unknown): boolean {
  // 简易实现，M2 换成 fast-deep-equal
  return JSON.stringify(a) === JSON.stringify(b)
}
```

**关键设计决策**：

1. **每次执行新建 Worker**：避免上次污染全局 —— 简单粗暴但正确
2. **约定式导出**：用户函数命名为题目要求的 `myPromiseAll` 等，Worker 通过约定名字取
3. **timeout 硬中断**：`worker.terminate()` 是唯一防死循环的方法
4. **不用 vm2 / quickjs**：过度设计，Worker 已够用

**面试话术**：见 [项目调研.md 第 10 节 Q2](项目调研.md#十面试话术准备每个亮点都要能答-5-层深)。

### 4.2 Agent Loop

**文件**：`lib/agent/loop.ts`

```typescript
import { streamText, tool } from 'ai'
import { deepseek } from '@ai-sdk/openai'
import { z } from 'zod'
import type { Session, Message } from '@/types'
import { tools } from './tools'
import { getPromptForRound } from './prompts'

export interface AgentContext {
  session: Session
  problem: ImplProblem
  currentCode: string
  testResults: TestResult[]
}

export async function* runAgentLoop(
  ctx: AgentContext,
  userMessage: string,
  signal: AbortSignal
): AsyncGenerator<{ type: 'text' | 'tool_call' | 'done'; data: any }> {
  const maxRounds = 10
  let round = 0

  const systemPrompt = getPromptForRound(ctx.session.outcome.currentRound, ctx)
  const messages = [
    { role: 'system' as const, content: systemPrompt },
    ...ctx.session.messages,
    { role: 'user' as const, content: userMessage },
  ]

  while (round < maxRounds) {
    round++

    const result = await streamText({
      model: deepseek('deepseek-chat'),
      messages,
      tools,
      abortSignal: signal,
      temperature: 0.3,
    })

    // 流式文本
    for await (const chunk of result.textStream) {
      yield { type: 'text', data: chunk }
    }

    // 工具调用
    const toolCalls = await result.toolCalls
    if (toolCalls && toolCalls.length > 0) {
      for (const call of toolCalls) {
        yield { type: 'tool_call', data: call }

        const toolResult = await executeTool(call.toolName, call.args, ctx)
        messages.push({
          role: 'assistant',
          content: '',
          toolCalls: [{ ...call, result: toolResult }],
        } as any)
        messages.push({
          role: 'tool' as any,
          content: JSON.stringify(toolResult),
        })
      }
      continue // 让 Agent 基于工具结果继续
    }

    // 没有工具调用 → 完成
    yield { type: 'done', data: null }
    break
  }
}

async function executeTool(name: string, args: any, ctx: AgentContext): Promise<any> {
  const tool = tools[name]
  if (!tool) throw new Error(`Unknown tool: ${name}`)
  return tool.execute(args, ctx)
}
```

**工具定义（示例）**：

```typescript
// lib/agent/tools/check-edge-case.ts
import { tool } from 'ai'
import { z } from 'zod'
import { runInSandbox } from '@/lib/sandbox/runner'

export const checkEdgeCase = {
  description: 'Check if user code correctly handles a specific edge case',
  parameters: z.object({
    edgeCaseId: z.string().describe('The ID of the edge case to check'),
  }),
  execute: async ({ edgeCaseId }: { edgeCaseId: string }, ctx: AgentContext) => {
    const edgeCase = ctx.problem.edgeCases.find((e) => e.id === edgeCaseId)
    if (!edgeCase) return { error: 'Edge case not found' }

    const testCases = ctx.problem.testCases.edge.filter((t) =>
      edgeCase.testCaseIds.includes(t.id)
    )
    const results = await runInSandbox(ctx.currentCode, testCases)
    const passed = results.every((r) => r.passed)

    return {
      passed,
      scenario: edgeCase.scenario,
      failedCases: results.filter((r) => !r.passed),
    }
  },
}
```

### 4.3 Prompt 组织（M1 起就要模块化）

**核心原则**：Prompt = 数据。不要写死在代码里，用模板函数。

```typescript
// lib/agent/prompts/round-0.ts
import type { AgentContext } from '../loop'

export function round0Prompt(ctx: AgentContext): string {
  return `你是一个前端资深工程师，正在陪一个求职者训练手撕题。

## 当前题目
${ctx.problem.title}

${ctx.problem.description}

## 用户当前代码
\`\`\`typescript
${ctx.currentCode || '(用户还没开始写)'}
\`\`\`

## 测试结果
${formatTestResults(ctx.testResults)}

## 你的任务（Round 0：基础实现引导）
- 如果用户还没写：用 1-2 个问题引导用户思考基础实现方向（不要给代码）
- 如果测试没通过：指出**通用问题方向**（例如"检查你的 return 位置"），不要指具体行号
- 如果基础测试通过：说 "很好，基础用例过了。我们进入 Round 1 边界追问。" 然后立即调用 \`start_round_1\` 工具

## 规则
- 禁止直接给出完整实现
- 单次回复不超过 2 行代码
- 语气：像一个耐心但会追问的面试官
- 用中文
`
}

function formatTestResults(results: TestResult[]): string {
  if (results.length === 0) return '(用户还没运行)'
  const passed = results.filter((r) => r.passed).length
  return `${passed}/${results.length} 通过\n${
    results
      .filter((r) => !r.passed)
      .map((r) => `  ✗ 期望 ${JSON.stringify(r.expected)}, 实际 ${JSON.stringify(r.actual)}`)
      .join('\n')
  }`
}
```

**Round 1-4 类似**，每个 Round 的 prompt 有：
- 当前状态注入（题目 / 代码 / 测试结果）
- 该轮的**目标**
- 该轮的**约束**（如 Round 1 明确"每次只追问 1 个 edge case"）

**M1-M3 用 localStorage 实现**：

```typescript
// lib/repo/local.ts
export class LocalSessionRepo implements SessionRepo {
  private key(id: string) {
    return `fedrill:session:${id}`
  }

  async create(session: Omit<Session, 'id'>): Promise<Session> {
    const id = crypto.randomUUID()
    const full = { ...session, id } as Session
    localStorage.setItem(this.key(id), JSON.stringify(full))
    return full
  }

  async get(id: string) {
    const raw = localStorage.getItem(this.key(id))
    return raw ? JSON.parse(raw) : null
  }
  // ...
}
```

## 6 · 状态管理

### 6.1 Zustand Store 划分

**Session Store**（题目做题状态）：

```typescript
// stores/session-store.ts
import { create } from 'zustand'
import { persist } from 'zustand/middleware'

interface SessionState {
  currentSessionId: string | null
  code: string
  testResults: TestResult[]
  messages: Message[]
  currentRound: 0 | 1 | 2 | 3 | 4 | 'completed'

  setCode: (code: string) => void
  setTestResults: (results: TestResult[]) => void
  appendMessage: (msg: Message) => void
  advanceRound: () => void
  reset: () => void
}

export const useSessionStore = create<SessionState>()(
  persist(
    (set) => ({
      currentSessionId: null,
      code: '',
      testResults: [],
      messages: [],
      currentRound: 0,
      setCode: (code) => set({ code }),
      setTestResults: (testResults) => set({ testResults }),
      appendMessage: (msg) => set((s) => ({ messages: [...s.messages, msg] })),
      advanceRound: () =>
        set((s) => ({
          currentRound: s.currentRound === 'completed'
            ? 'completed'
            : ((s.currentRound + 1) as any),
        })),
      reset: () => set({ code: '', testResults: [], messages: [], currentRound: 0 }),
    }),
    { name: 'fedrill-session' }
  )
)
```

## 8 · 开发规范

### 8.1 Git 提交规范（Conventional Commits）

```text
<type>(<scope>): <subject>

Types:
  feat     - 新功能
  fix      - Bug 修复
  refactor - 重构
  perf     - 性能优化
  docs     - 文档
  style    - 格式（不影响代码运行）
  test     - 测试
  chore    - 构建/工具/依赖

Examples:
  feat(sandbox): implement web worker code execution
  fix(agent): handle empty tool call response
  refactor(prompts): extract shared prompt utilities
  docs: update PRD with M2 features
```

### 8.2 分支规范

- `main` —— 主分支，永远可部署
- `feat/xxx` —— 功能开发
- `fix/xxx` —— Bug 修复

M1-M2 单人开发直接 push main 也可。M3+ 建议开 PR 走 CI。

### 8.3 命名规范

- **文件**：kebab-case（`code-editor.tsx`）
- **组件**：PascalCase（`CodeEditor`）
- **函数/变量**：camelCase
- **常量**：SCREAMING_SNAKE_CASE
- **类型**：PascalCase（`ImplProblem`）
- **hook**：`use` 前缀

### 8.4 组件组织规范

**每个组件文件包含**：

```typescript
'use client' // 如需

import ...

interface Props {
  ...
}

export function ComponentName({ ... }: Props) {
  // 1. hooks
  // 2. state
  // 3. computed / callbacks
  // 4. effects
  // 5. render
}
```

**Server Components 优先**：除非需要交互，默认不加 `'use client'`。

### 8.5 错误处理规范

- **业务错误**：抛具名 Error 子类（`class SandboxTimeoutError extends Error`）
- **UI 错误**：`error.tsx` boundary + toast
- **服务端错误**：Route Handler 返回 4xx/5xx JSON，前端解析

## 9 · 关键技术决策记录（ADR）

### ADR-001 · 用 Web Worker 而非 iframe 做沙箱

**决策**：Web Worker

**上下文**：需要在浏览器隔离执行用户 JS 代码。

**候选**：iframe / Web Worker / vm2 / QuickJS-emscripten

**理由**：

- iframe 通信复杂（postMessage 但生命周期难管）
- vm2 Node.js 专用，浏览器跑不了
- QuickJS 太重（几 MB WASM）
- Web Worker 原生支持 + terminate + postMessage 简洁

**代价**：Worker 里没法用 DOM API，但手撕题基本不需要。

---

### ADR-002 · 用 Zustand 而非 Redux

**决策**：Zustand

**上下文**：需要跨组件共享 session 状态。

**理由**：

- Redux boilerplate 太多
- Jotai 原子化对当前粒度过度
- Zustand 一个 create 就是 store，学习成本 30 分钟

---

### ADR-003 · M1-M3 用 localStorage，M4 才引入数据库

**决策**：先本地后云端

**上下文**：早期用户 = 你自己，不需要跨设备同步。

**理由**：

- 少一个部署依赖（Supabase 也要配置）
- 用 Repository Pattern 抽象，切换成本低
- M4 加认证时才有必要云端

---

### ADR-004 · Agent Loop 自研而非用 LangChain

**决策**：自研

**理由**：

- LangChain 是黑盒，面试问不出细节
- 自研 200 行代码搞定 ReAct，可控可讲
- Vercel AI SDK 已经封装了流式和 tool call，够用

---

### ADR-005 · 用 Server Actions 而非 REST API

**决策**：混合

- 前端调用为主 → Server Actions（类型安全，无手写 fetch）
- 需要流式返回 → Route Handler（Server Actions 不支持流）
- 外部调用（MCP）→ Route Handler

**理由**：Server Actions 类型推导自动，减少 boilerplate。

---

### ADR-006 · 题库用 TS 文件而非 JSON

**决策**：TS

**理由**：

- 每题有 code 字段，用模板字符串 + TS 类型检查更爽
- 编辑器智能提示 + 编译期错误
- 未来动态生成变体题时纯 TS 好写

**代价**：题目不能热更新（每次改要重新构建），但 M1-M4 单人开发无所谓。

---

### ADR-007 · 不引入 UI 组件库（MUI/AntD），用 shadcn/ui

**决策**：shadcn/ui

**理由**：

- shadcn 不是 npm 包，是复制代码，完全可控
- Tailwind 生态，跟 Next.js 15 无缝
- 组件在你 repo 里，可以随意改
