## 1 · 产品概述

### 1.1 一句话定义

FEDrill 是一个**前端秋招题库 AI 教练**，用面试官风格的追问帮前端求职者训练手撕题、算法题、八股题。

### 1.2 核心价值主张

| 用户痛点 | FEDrill 提供的价值 |
| --- | --- |
| ChatGPT 一问就给答案，学不到东西 | AI 只追问不给答案，逼你自己想 |
| 手撕题背了答案没深度，面试被追问就崩 | **阶梯式追问**：基础 → 边界 → 性能 → 工程化 |
| 八股知识点太多背了忘 | **对话式深挖 + SRS 间隔重复** |
| 不知道自己弱在哪 | **三维度能力雷达图 + 弱点画像** |

### 1.3 成功指标（个人项目视角）

**MVP 完成标准**（M1-M2）：

- 能给别人现场演示手撕题完整流程
- 至少覆盖 4 类共 15 道手撕题
- Agent 追问逻辑走通 Round 0-4

**秋招投递标准**（M3 结束）：

- 简历上能写至少 4 条技术亮点
- GitHub 仓库有清晰 README + Demo GIF
- 项目部署到公开 URL 可访问
- 有面试话术清单（每个功能能讲 5 层深）

## 2 · 用户画像与场景

### 2.1 主要用户

**Persona P1 · 前端秋招求职者**（就是你）

- 大三/大四 or 应届生
- 有 React 基础，能写小项目
- 焦虑：简历没亮点、手撕题不熟、八股背了忘
- 每天投入：1-2 小时（碎片时间）
- 使用场景：地铁、实习摸鱼、睡前

### 2.2 次要用户

**Persona P2 · 想跳槽的初中级前端**

- 工作 1-3 年
- 需要系统性复盘前端知识
- 使用场景：面试前 1-2 周集训

### 2.3 核心使用场景

**S1 · 每日 30 分钟训练**：打开 → 从推荐题里选一道 → 完成 Round 0-4 追问 → 关掉

**S2 · 复习模式**：进入 SRS 待复习列表 → 快速走 3-5 道八股题 → 更新掌握度

**S3 · 面试前突击**：按分类筛选（如"异步控制"）→ 集中训练 → 看能力雷达是否补齐

**S4 · 展示给面试官**：面试时打开项目 → 现场演示"AI 面试官追问我一道 Promise.all" → 面试官进入产品思维讨论

```text

  ↓
看到"AI 面试官陪练"介绍 + 3 个演示 GIF
  ↓
点"试用（无需注册）" → 直接进入手撕题列表
  ↓
```

#### F-002 · Monaco 代码编辑器 · P0 · M1-D3

**描述**：集成 Monaco Editor 作为手撕/算法题的代码输入区。

**验收标准**：

- [ ] 支持 TypeScript / JavaScript 高亮
- [ ] 支持基础智能提示（自动补全、跳转定义）
- [ ] 暗色主题
- [ ] 用户代码自动保存到 localStorage（题目 ID 作为 key）
- [ ] `Ctrl+Enter` 触发"运行"
- [ ] 支持字体大小调整
- [ ] Tab 缩进 = 2 空格

**边界**：不做代码格式化（Prettier 集成放 P1）。

---

#### F-003 · Web Worker 代码执行沙箱 · P0 · M1-D5

**描述**：在浏览器 Web Worker 里执行用户 JS 代码，跑测试用例，返回结果。

**验收标准**：

- [ ] 用户代码通过 postMessage 传入 Worker
- [ ] Worker 执行代码 + 每个测试用例
- [ ] 返回 `{ passed: boolean, actual, expected, error }[]`
- [ ] 主线程 3 秒超时 → `worker.terminate()`
- [ ] 捕获 syntax error / runtime error / infinite loop
- [ ] 每次执行创建新 Worker（避免上一次代码污染）

**技术要点**：

```typescript
// lib/sandbox/runner.ts
type TestCase = { input: unknown[]; expected: unknown }
type TestResult = { passed: boolean; actual?: unknown; expected: unknown; error?: string }

async function runInSandbox(code: string, cases: TestCase[], timeoutMs = 3000): Promise<TestResult[]>
```

**边界**：不支持异步测试用例断言（Promise 测试通过 return Promise 判断，不用 assert 库）。

---

#### F-004 · LLM 流式对话 · P0 · M1-D7

**描述**：接入 DeepSeek API，用 Vercel AI SDK 实现流式对话。

**验收标准**：

- [ ] `/api/chat` 路由能接收消息数组返回流式响应
- [ ] 前端用 `useChat` hook 消费
- [ ] Markdown 渲染 + 代码块高亮（用 `react-markdown` + `shiki` 或 `react-syntax-highlighter`）
- [ ] 打字机效果流畅（无卡顿）
- [ ] 用户能中断当前生成
- [ ] 错误处理（API 失败友好提示）

**边界**：M1 只做单会话；多会话切换放 P1。

#### F-104 · 手撕题预置数据 · P0 · M1-D4 → M2 持续补充

**描述**：手工整理核心 30 道手撕题。

**M1 起步 5 题**（D4 完成）：

1. 手写 debounce
2. 手写 deepClone
3. 手写 Promise.all
4. 手写 call
5. 手写 EventEmitter

**M2 完成 30 题**（每类 7-8 道）：

- **异步控制**：Promise.all/race/allSettled/any、pLimit、可取消 Promise、重试、超时（7 道）
- **原型链**：new、call/apply/bind、instanceof、Object.create、寄生组合继承（7 道）
- **工具函数**：debounce/throttle、deepClone、curry、flat、compose、once、memoize（8 道）
- **设计模式**：EventEmitter、观察者、发布订阅、单例、代理、工厂、责任链（8 道）

**每题必须包含**：

```typescript
interface ImplProblem {
  id: string
  title: string
  category: 'async' | 'prototype' | 'util' | 'pattern'
  difficulty: 'easy' | 'medium' | 'hard'
  description: string        // Markdown 支持
  requiredAPI: string        // 如 "myPromiseAll"
  starterCode: string        // 初始模板
  testCases: {
    basic: TestCase[]        // Round 0 用（3-5 个）
    edge: TestCase[]         // Round 1 用（5-10 个）
    stress: TestCase[]       // Round 2 用（性能测试）
  }
  edgeCases: {               // 供 Agent 追问用的具体场景描述
    id: string
    scenario: string         // "第 3 个 Promise reject 时"
    hint: string             // "试试 Promise.all([resolve(1), reject('boom'), p3])"
  }[]
  followUpPath: {
    round1: string[]         // 边界追问点
    round2: string[]         // 性能追问点
    round3: string[]         // 工程化追问点
    round4: string[]         // 变体延伸题目 ID
  }
  referenceImpls: {
    label: string            // "简洁版" / "工程版" / "极简版"
    code: string
    explanation: string
  }[]
}
```

**边界**：M1 每题只要 `basic testCases + 3 个 edgeCases + Round 1 追问点` 即可，其他 M2 补齐。

#### F-105 · 苏格拉底 Round 0 Agent（v0）· P0 · M1-D9

**描述**：Agent 在 Round 0 引导用户给基础实现。

**验收标准**：

- [ ] System prompt 明确"不给答案、只引导"
- [ ] 能读到当前题目描述 + 当前代码 + 测试结果
- [ ] 用户点"我不会写" → Agent 提供**思路提示**（不是代码）
- [ ] 用户提交代码通过基础测试 → Agent 说"好，进入 Round 1 边界追问"

**System prompt 模板**（Round 0）：

```text
你是一个前端面试官，正在陪用户练习手撕题。当前题目：{title}
用户目前的代码：{code}
测试结果：{testResults}

你的任务：
1. 如果用户还没写代码，用问题引导用户思考基础实现方向（不给代码）
2. 如果测试没通过，指出通用问题（不指出具体行号）
3. 如果通过基础测试，宣布进入下一 Round

禁止：
- 直接给出完整实现
- 一次给超过 2 行代码
```

#### F-107 · Round 1 边界追问 · P0 · M2-D16

**描述**：进入 Round 1 后，Agent 从题目预设的 edgeCases 挑一个用户没覆盖的进行追问。

**验收标准**：

- [ ] Agent 用 `check_edge_case` 工具判断用户代码是否覆盖某边界
- [ ] 按预设的 edgeCases 顺序追问，跳过用户已通过的
- [ ] 用户改代码 → 重新跑对应 edge case → 通过则下一个
- [ ] 所有 edge case 通过 → 进入 Round 2

---

#### F-108 · Round 2 性能追问 · P1 · M2-D18

**描述**：分析用户代码复杂度，追问优化空间。

**验收标准**：

- [ ] 用 Babel Parser 解析用户代码 AST
- [ ] Agent 有 `analyze_complexity` 工具（返回时间/空间复杂度估算）
- [ ] Agent 追问："能优化到 O(n) 吗?"
- [ ] 用户提交优化版 → 通过 stress 测试 → 进入 Round 3

**边界**：复杂度分析是 heuristic，不追求 100% 准确。

## 5 · 数据模型

### 5.1 核心类型（TypeScript 定义）

```typescript
// 题目通用
type ProblemType = 'implementation' | 'algorithm' | 'theory'
type Difficulty = 'easy' | 'medium' | 'hard'

interface TestCase {
  input: unknown[]
  expected: unknown
  description?: string
}

interface BaseProblem {
  id: string
  type: ProblemType
  title: string
  difficulty: Difficulty
  tags: string[]
  description: string  // Markdown
}

// 手撕题
interface ImplProblem extends BaseProblem {
  type: 'implementation'
  category: 'async' | 'prototype' | 'util' | 'pattern'
  requiredAPI: string
  starterCode: string
  testCases: {
    basic: TestCase[]
    edge: TestCase[]
    stress: TestCase[]
  }
  edgeCases: EdgeCase[]
  followUpPath: FollowUpPath
  referenceImpls: ReferenceImpl[]
}

interface EdgeCase {
  id: string
  scenario: string
  hint: string
  testCaseIds: string[]  // 关联 testCases.edge 中的 case
}

interface FollowUpPath {
  round1: string[]  // edge case IDs
  round2: string[]  // 性能追问点（自由文本）
  round3: string[]  // 工程化追问点
  round4: string[]  // 变体题 problem IDs
}

interface ReferenceImpl {
  label: string
  code: string
  explanation: string
}

// 算法题（M3）
interface AlgorithmProblem extends BaseProblem {
  type: 'algorithm'
  testCases: TestCase[]
  timeLimit: number  // ms
  memoryLimit: number  // MB
  hintLevels: string[]  // 5 层提示
  visualizationType?: 'array' | 'linkedlist' | 'tree' | 'dp' | 'graph'
}

// 八股题（M4）
interface TheoryProblem extends BaseProblem {
  type: 'theory'
  domain: 'js-basic' | 'js-async' | 'browser' | 'network' | 'react' | 'css' | 'engineering' | 'perf' | 'security'
  question: string
  rubric: {
    keyPoints: string[]     // 3-5 个关键点
    depth: 'shallow' | 'medium' | 'deep'
  }
  followUps: string[]
  relatedTopicIds: string[]
}

// 会话（用户与 Agent 的一次交互）
interface Session {
  id: string
  userId?: string  // 未注册用户为空
  problemId: string
  messages: Message[]
  outcome: {
    currentRound: 0 | 1 | 2 | 3 | 4 | 'completed'
    testResults: TestResult[]
    hintsUsed: number
  }
  createdAt: Date
  updatedAt: Date
}

interface Message {
  role: 'user' | 'assistant' | 'system'
  content: string
  toolCalls?: ToolCall[]
  timestamp: Date
}

interface ToolCall {
  name: string
  args: Record<string, unknown>
  result?: unknown
}

// SRS 卡片（M4）
interface SRSCard {
  userId: string
  problemId: string
  interval: number         // 天
  easeFactor: number       // 2.5 起始
  repetitions: number
  nextReview: Date
  lastQuality: 0 | 1 | 2 | 3 | 4 | 5  // SM-2 质量评分
}

// 用户 Profile（M4）
interface UserProfile {
  userId: string
  skillMatrix: {
    algorithm: number       // 0-100
    implementation: {
      async: number
      prototype: number
      util: number
      pattern: number
    }
    theory: Record<string, number>  // domain → 掌握度
  }
  streak: number  // 连续天数
  totalCompleted: number
}
```

### 5.2 数据库表（Supabase）

```sql
-- M1-M3 用 localStorage 即可，M4 引入数据库

users        (id, email, github_id, created_at)
problems     (id, type, data JSONB, updated_at)  -- 静态题库
sessions     (id, user_id, problem_id, data JSONB, created_at, updated_at)
srs_cards    (user_id, problem_id, interval, ease_factor, next_review, ...)
user_profile (user_id, skill_matrix JSONB, streak, total_completed)
```

### 6.3 关键交互规范

- **快捷键**：
  - `Ctrl/Cmd + Enter` = 运行代码
  - `Ctrl/Cmd + K` = 打开命令面板（M4）
  - `Esc` = 中断 Agent 生成
- **状态提示**：所有异步操作有 loading / success / error 三态
- **错误处理**：网络错误显示 toast，可点重试
- **暗色主题**：默认暗色，可切换（M2）

## 7 · 非功能需求

### 7.1 性能

| 指标 | 目标 |
| --- | --- |
| 首屏加载（FCP） | < 1.5s |
| Web Worker 冷启动 | < 100ms |
| LLM 首 token | < 1.5s |
| 代码执行超时 | 3s（硬上限） |
| Monaco 大文件（> 500 行） | 输入无感 |

### 7.2 成本

| 项 | 上限 |
| --- | --- |
| DeepSeek API 月成本 | < ¥50 |
| Supabase 免费额度 | 不超（500MB DB / 1GB 存储 / 50K 月活） |
| Vercel 免费额度 | 不超（100GB 流量 / 无限静态） |
| Piston API（M3）| 走免费公共 endpoint（有限流兜底） |

**成本控制手段**：

- LLM 请求缓存（Redis）
- 每用户每日 Token 上限（默认 50K）
- 空闲会话主动断开

### 7.3 安全

- 用户代码在 Web Worker 隔离执行（防死循环，非防恶意）
- API Key 只在服务端使用（不暴露到前端）
- Supabase RLS（行级安全）
- 不存储敏感信息

### 7.4 可用性 / SLA

- 个人项目，不承诺 SLA
- 但要求：**演示 demo 不崩**（面试关键场景兜底）
