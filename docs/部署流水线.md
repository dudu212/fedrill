# 部署流水线（GitHub Actions）

> CI 在 GitHub 上构建 `standalone` 自包含产物 → SSH 上传 → 服务器只跑不 build。
> 彻底根治 Turbopack「上传产物丢软链 → ERR_MODULE_NOT_FOUND」，机制见 [turbopack-external-module-symlink.md](learning/turbopack-external-module-symlink.md)。

## 架构

```
push 到 main
   └─> GitHub Actions（.github/workflows/deploy.yml）
        1. checkout + 装 Node 20 / pnpm 11.17
        2. pnpm install + pnpm build（output: standalone）
        3. 迁移 DB：SSH 隧道把服务器 PG 映射到 CI，跑 migrate-problems.ts
        4. 打包 .next/standalone + .next/static + public → tar
        5. scp 上传 → 服务器解压到新目录 → 停服 → 换目录 → 起服
```

## 一次性服务器准备（只在第一次做）

### 1. 装 deploy key

在**你自己的电脑**上生成一对 key（不要用服务器已有 key）：

```bash
ssh-keygen -t ed25519 -C "github-actions-deploy" -f ~/.ssh/fedrill_deploy -N ""
```

把**公钥**（`~/.ssh/fedrill_deploy.pub` 内容）追加到服务器的 `~/.ssh/authorized_keys`：

```bash
# 服务器上执行
mkdir -p ~/.ssh && chmod 700 ~/.ssh
echo "ssh-ed25519 AAAA... 公钥内容" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
```

把**私钥**（`~/.ssh/fedrill_deploy` 内容）存到 GitHub Secrets 的 `SSH_PRIVATE_KEY`。

### 2. 改 systemd 单元为 standalone

现在服务跑的是 `next start`；standalone 产物没有 `next` CLI，入口是 `server.js`。把单元改成：

```ini
[Unit]
Description=FEDrill Next.js App (standalone)
After=network.target docker.service

[Service]
Type=simple
User=lx
WorkingDirectory=/home/lx/fedrill
Environment=NODE_ENV=production
Environment=PORT=3000
Environment=HOSTNAME=0.0.0.0
EnvironmentFile=/home/lx/fedrill/.env.local
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl restart fedrill   # 服务名以实际为准
```

> `HOSTNAME=0.0.0.0` 必须显式写：Linux 的 `HOSTNAME` 默认是机器名，standalone 会误把它当绑定地址。
> `EnvironmentFile` 显式注入 `.env.local`，不依赖 Next 是否自动加载环境文件。

### 3. 确保 `lx` 有免密 sudo（否则 CI 里 `systemctl restart` 会卡住）

```bash
sudo visudo -f /etc/sudoers.d/lx-deploy
# 写入这一行：
lx ALL=(ALL) NOPASSWD: /usr/bin/systemctl
```

### 4. 确认 `.env.local` 位置

部署脚本假设它在 `~/fedrill/.env.local`。确认它在、且 `DATABASE_URL` 指向的是现在有 15 道题的那个库。

| 名称 | 值 |
| --- | --- |
| `SSH_PRIVATE_KEY` | 第 1 步生成的私钥全文 |
| `SSH_HOST` | `47.236.125.126` |
| `SSH_USER` | `lx` |

## 触发与回滚

- **触发**：push 到 main，或 Actions 页手动 `workflow_dispatch`。
- **回滚**：每次部署会把上一版移到 `~/fedrill-backup-<时间戳>`。出问题时：

```bash
sudo systemctl stop fedrill
mv ~/fedrill ~/fedrill-bad
mv ~/fedrill-backup-<时间戳> ~/fedrill
sudo systemctl start fedrill
```

## 改域名 / DB 账号时改哪里

- **改域名**：`deploy.yml` 里 `NEXT_PUBLIC_APP_URL`，以及服务器 `.env.local` 的 `APP_BASE_URL`。
- **DB 账号不是 ddd/ddd**：改 `deploy.yml` 里 `Migrate DB` 那步的 `DATABASE_URL`（隧道端口保持 15432 不变）。
